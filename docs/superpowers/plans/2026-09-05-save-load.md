# Save and Load Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Five save slots, a start screen with NEW GAME / LOAD GAME, and SAVE GAME in the escape menu, per `docs/superpowers/specs/2026-09-05-save-load-design.md`.

**Architecture:** A new `CubeForge.Save` module owns the on-disk format (a directory per slot: 64 raw chunk files and a text header written last). The menu becomes a mode/page state machine drawn by `Hud` from one geometry source. `run_session` takes a start descriptor (seed or slot); loading reuses the whole new-game pipeline after `World.from_chunks`. Water actors read their own chunk file on `WLoadSlot` (stopgap until messages can carry byte arrays); the weather actor gains snapshot/restore.

**Tech Stack:** March (`.march`), `forge test` / `forge build --release`, stdlib `File`, `Dir`, `Bytes`, `String.to_int/to_float`, `DateTime.now`.

## Global Constraints

- Toolchain pinned by `.march-version` (`watch-ac782d80`). Run `forge test` for the suite; refinement "unverifiable obligation" hints are noise.
- Labels use digits and upper-case letters only (the HUD font).
- Actor messages cannot carry native arrays (GAPS G44); `Actor.call` is unavailable under `forge test` (GAPS G49).
- Message constructors are only in scope inside their module and after the actor declaration (GAPS G46): drive actors via wrapper functions.
- Header keys and layout exactly as the spec §2 table. `version` is `1`, `side` is `8`.
- Save dir: `saves` under the cwd, or `CF_SAVE_DIR`.
- No attribution lines in commits.

### Task 1: `CubeForge.Save` header encode/parse

**Files:**
- Create: `lib/cube_forge/save.march`
- Test: `test/save_test.march`

**Interfaces (produces):**
```march
type Header = Header(Int, Int, Int, NativeFloatArr, NativeIntArr, Float, NativeFloatArr)
-- version, side, seed, saved_at packed? no: see accessors below
```
Concretely:
```march
-- seed, saved_at, player [px py pz vx vy vz yaw pitch] (8 floats), inventory (72 ints + sel = 73 ints), day, weather [phase ticks intensity*1e6 bolt*1e6] as 4 floats
type Header = Header(Int, Int, NativeFloatArr, NativeIntArr, Float, NativeFloatArr)
fn version() : Int do 1 end
fn header_new(seed, saved_at, player : NativeFloatArr, inv : NativeIntArr, day : Float, wx : NativeFloatArr) : Header
fn h_seed(h) / h_saved_at(h) / h_player(h) / h_inventory(h) / h_day(h) / h_weather(h)
fn encode_header(h : Header, side : Int) : String
fn parse_header(s : String, side : Int) : Result(Header, String)
```
`encode_header` writes lines `version 1`, `side 8`, `seed N`, `saved_at N`, `player f f f f f f f f`, `inventory i*73`, `day f`, `weather f f f f`. `parse_header` splits on `"\n"`, each line on `" "`, ignores unknown keys, errors on: missing key, `version != version()`, `side != side`, wrong arity, unparsable number.

  - "a wrong version is rejected": replace `version 1` with `version 2`.
